Chapter 2: Maximum Likelihood Estimation

Runs in the browser -- click the power icon above to start the kernel -- or in Colab, which has a full Python and a live network.

Given data assumed to come from a parametric family, MLE picks the parameter values that make the data we actually saw the most probable thing to have observed (for continuous data, the most dense — any exact value has probability zero).

Running the code

The Python cells on this page run in your browser. Click the power icon at the top of the page to activate the kernel, then run — or edit — any cell. Packages (NumPy, SciPy, …) load automatically the first time you import them (a few seconds).

Motivation¶

You have data — a sequence of coin flips, a list of game outcomes, a daily stock return — and a candidate probabilistic model for how it was produced. The model has unknown parameters θ\thetaθ (a probability, a mean and variance, a rate). What value of θ\thetaθ should you commit to?

MLE answers: pick the θ\thetaθ that maximizes the probability of the data you actually observed. It is the simplest principled way to fit a probabilistic model, and almost everything later in the book — Monte Carlo error analysis, fitting random-walk drifts, calibrating a GBM, identifying the tail class in extreme value statistics — invokes it.

Setup & notation¶

Assume nnn independent and identically distributed (IID) observations

X1,X2,…,Xn∼iidf(⋅∣θ),X_1, X_2, \dots, X_n \overset{\text{iid}}{\sim} f(\cdot \mid \theta),X1​,X2​,…,Xn​∼iidf(⋅∣θ),
(1)

where f(x∣θ)f(x \mid \theta)f(x∣θ) is a probability density (continuous data) or mass function (discrete data) and θ\thetaθ is the unknown parameter (or vector of parameters) we want to estimate.

Symbols come from A_notation.md. New here:

  • L(θ)L(\theta)L(θ) — likelihood: the joint mass (discrete data) or density (continuous data) of the observed sample, read as a function of θ\thetaθ.

  • ℓ(θ)=log⁡L(θ)\ell(\theta) = \log L(\theta)ℓ(θ)=logL(θ) — log-likelihood.

  • NLL(θ)=−ℓ(θ)\mathrm{NLL}(\theta) = -\ell(\theta)NLL(θ)=−ℓ(θ) — what numerical solvers minimize.

  • θ^MLE\hat{\theta}_{\mathrm{MLE}}θ^MLE​ — the MLE, the argmax of LLL (equivalently of ℓ\ellℓ).

Core ideas¶

The likelihood¶

By independence, the joint density factorizes:

L(θ)=∏i=1nf(Xi∣θ).L(\theta) = \prod_{i=1}^{n} f(X_i \mid \theta).L(θ)=i=1∏n​f(Xi​∣θ).
(2)

The crucial conceptual move: L(θ)L(\theta)L(θ) is read as a function of the parameter, with the data XiX_iXi​ held fixed. Pre-experiment, f(X∣θ)f(X \mid \theta)f(X∣θ) is “the probability of XXX given θ\thetaθ.” Post-experiment, L(θ)L(\theta)L(θ) ranks candidate θ\thetaθ’s by how well each accounts for what I saw. Same expression, different perspective. Resist upgrading that ranking into “how probable is each θ\thetaθ” — LLL is not a distribution over θ\thetaθ and does not integrate to 1. Exercise 1 is about exactly this.

Why log-likelihood¶

Two excellent reasons to maximize ℓ=log⁡L\ell = \log Lℓ=logL instead of LLL directly:

  1. Algebra. Products of nnn terms become sums:

    ℓ(θ)=∑i=1nlog⁡f(Xi∣θ).\ell(\theta) = \sum_{i=1}^{n} \log f(X_i \mid \theta).ℓ(θ)=i=1∑n​logf(Xi​∣θ).
    (3)

    Derivatives of sums are easy; derivatives of products are a chain-rule nightmare.

  2. Numerics. LLL multiplies nnn small factors together, so it shrinks geometrically in nnn. For a fair coin, any specific sequence of nnn flips has likelihood exactly 2−n2^{-n}2−n: at n=100n = 100n=100 that is ≈10−30\approx 10^{-30}≈10−30, and by n=1075n = 1075n=1075 it has rounded to zero in double precision and the estimate is destroyed. ℓ=log⁡L\ell = \log Lℓ=logL turns that product into a sum and stays in a sane numerical range — at n=1075n = 1075n=1075 it is a perfectly ordinary -745.

    Two things this argument does not say. The bound is not 2−n2^{-n}2−n in general — for a biased coin the largest a likelihood can get is max⁡(p,1−p)n\max(p, 1-p)^nmax(p,1−p)n, so all-heads data under p=0.9p = 0.9p=0.9 gives 0.9100≈3×10−50.9^{100} \approx 3 \times 10^{-5}0.9100≈3×10−5, twenty-five orders of magnitude above 2-100. And the factors are not always ≤1\le 1≤1: for continuous data they are densities, which can exceed 1 wherever the distribution is concentrated (N(0,0.01)\mathcal{N}(0, 0.01)N(0,0.01) has density 3.99 at the origin). Underflow is still the rule in practice, because nnn factors that are typically small still collapse; but “each term is a probability below one” is the wrong reason.

Since log⁡\loglog is strictly increasing, the argmax is the same: arg⁡max⁡θL(θ)=arg⁡max⁡θℓ(θ)\arg\max_\theta L(\theta) = \arg\max_\theta \ell(\theta)argmaxθ​L(θ)=argmaxθ​ℓ(θ).

Two ways to find the maximum¶

Analytic. When ℓ\ellℓ is smooth and unimodal in θ\thetaθ, set ∇θℓ=0\nabla_\theta \ell = 0∇θ​ℓ=0 and solve. For many “textbook” distributions (Bernoulli, Gaussian, exponential, Poisson) this gives a closed form — usually a function of the sample mean or sample variance.

Numeric. When the model is more complicated — θ\thetaθ enters through a neural network, a system of ODEs, a tournament simulation — there is no closed form. We hand the negative log-likelihood to an optimizer (scipy.optimize.minimize, etc.) and minimize it. Always pass NLL, not −L-L−L: optimizers minimize, and the log keeps the surface numerically tame.

Aside: concavity is a separate question. Maximising wants ℓ\ellℓ concave in θ\thetaθ — equivalently, the NLL −ℓ-\ell−ℓ convex. Get the direction right: a convex ℓ\ellℓ would push its maximum out to the boundary, which is the opposite of what you want. When ℓ\ellℓ is concave, any local maximum is the global one and gradient methods cannot get stuck in a spurious peak. It holds for many simple distributions (Bernoulli in ppp, Gaussian in μ\muμ at fixed σ\sigmaσ) — for Bernoulli, ℓ′′(p)=−S/p2−(n−S)/(1−p)2<0\ell''(p) = -S/p^2 - (n-S)/(1-p)^2 < 0ℓ′′(p)=−S/p2−(n−S)/(1−p)2<0 on (0,1)(0,1)(0,1), which is exactly the concavity check. It usually fails as soon as θ\thetaθ enters fff nonlinearly (e.g. ℓ\ellℓ is not jointly concave in (μ,σ2)(\mu, \sigma^2)(μ,σ2), and any neural-net likelihood is wildly non-concave). When in doubt, run the optimizer from multiple random starts.

Worked example 1: Bernoulli ppp¶

You flip a possibly-biased coin nnn times and record Xi∈{0,1}X_i \in \{0, 1\}Xi​∈{0,1} with Xi∼Bernoulli(p)X_i \sim \mathrm{Bernoulli}(p)Xi​∼Bernoulli(p). Estimate ppp.

Analytic derivation¶

The Bernoulli pmf can be written compactly as f(x∣p)=px(1−p)1−xf(x \mid p) = p^x (1-p)^{1-x}f(x∣p)=px(1−p)1−x (check: f(1)=pf(1) = pf(1)=p, f(0)=1−pf(0) = 1-pf(0)=1−p). So

ℓ(p)=∑i=1n[Xilog⁡p+(1−Xi)log⁡(1−p)]=Slog⁡p+(n−S)log⁡(1−p),\ell(p) = \sum_{i=1}^n \big[X_i \log p + (1 - X_i) \log(1-p)\big] = S \log p + (n - S) \log(1 - p),ℓ(p)=i=1∑n​[Xi​logp+(1−Xi​)log(1−p)]=Slogp+(n−S)log(1−p),
(4)

where S=∑iXiS = \sum_i X_iS=∑i​Xi​ is the number of successes. Differentiate, set to zero:

dℓdp=Sp−n−S1−p=0⟹p^MLE=Sn=Xˉ.\frac{d\ell}{dp} = \frac{S}{p} - \frac{n - S}{1 - p} = 0 \quad\Longrightarrow\quad \boxed{\hat{p}_{\mathrm{MLE}} = \frac{S}{n} = \bar{X}}.dpdℓ​=pS​−1−pn−S​=0⟹p^​MLE​=nS​=Xˉ​.
(5)

The MLE is the sample mean. This is so familiar that it can feel circular, but the value of the derivation is in the justification: out of every possible estimator (median? mode? median-of-medians? something exotic?), MLE picks the sample mean for a principled reason.

Numeric verification¶

Even though we have a closed form, it is worth seeing the numerical path because the same code structure works for models without one.

import numpy as np
from scipy.optimize import minimize

rng = np.random.default_rng(seed=0)
p_true, n = 0.3, 500
data = rng.binomial(1, p_true, size=n)

def nll_bernoulli(p, x):
    p = np.clip(p, 1e-9, 1 - 1e-9)   # avoid log(0)
    return -np.sum(x * np.log(p) + (1 - x) * np.log(1 - p))

p_analytic = data.mean()
p_numeric = minimize(nll_bernoulli, x0=0.5, args=(data,),
                     bounds=[(1e-9, 1 - 1e-9)]).x.item()

print(p_true, p_analytic, p_numeric)
# 0.3   0.338   0.338

The two estimates agree to within optimizer tolerance, as they must — there is only one minimum of a convex function. Both differ from ptrue=0.3p_{\text{true}} = 0.3ptrue​=0.3 by about 0.04, which is right in line with the standard error p(1−p)/n≈0.020\sqrt{p(1-p)/n} \approx 0.020p(1−p)/n​≈0.020 (we are ∼2σ\sim 2\sigma∼2σ off, well within the noise of a single sample).

The full version (parameter sweep + plot of the NLL curve with both estimates marked) is in code/02_mle/bernoulli_mle.py.

Worked example 2: sum of two Bernoulli flips¶

Now each observation XiX_iXi​ is the sum of two independent Bernoulli(p)(p)(p) trials, so Xi∈{0,1,2}X_i \in \{0, 1, 2\}Xi​∈{0,1,2} with

P(X=0)=(1−p)2,P(X=1)=2p(1−p),P(X=2)=p2.\mathbb{P}(X = 0) = (1-p)^2, \qquad \mathbb{P}(X = 1) = 2p(1-p), \qquad \mathbb{P}(X = 2) = p^2.P(X=0)=(1−p)2,P(X=1)=2p(1−p),P(X=2)=p2.
(6)

(In other words, Xi∼Binomial(2,p)X_i \sim \mathrm{Binomial}(2, p)Xi​∼Binomial(2,p).)

This is the simplest example where the observation is no longer a single Bernoulli but a derived random variable — the kind of structure that shows up everywhere in modeling (a tournament outcome is a sum of match outcomes; a stock price is a product of returns).

Analytic derivation¶

Let n0,n1,n2n_0, n_1, n_2n0​,n1​,n2​ be the counts of each outcome in NNN trials (n0+n1+n2=Nn_0 + n_1 + n_2 = Nn0​+n1​+n2​=N). Then

ℓ(p)=n0log⁡[(1−p)2]+n1log⁡[2p(1−p)]+n2log⁡[p2].\ell(p) = n_0 \log[(1-p)^2] + n_1 \log[2p(1-p)] + n_2 \log[p^2].ℓ(p)=n0​log[(1−p)2]+n1​log[2p(1−p)]+n2​log[p2].
(7)

Differentiating, setting to zero, and solving (a few lines of algebra):

p^MLE=2n2+n12N.\hat{p}_{\mathrm{MLE}} = \frac{2 n_2 + n_1}{2 N}.p^​MLE​=2N2n2​+n1​​.
(8)

This is again a sample mean — but now of individual coin outcomes, not of XiX_iXi​. Out of 2N2N2N underlying coin flips, 2n2+n12 n_2 + n_12n2​+n1​ came up heads.

Numeric estimate¶

import numpy as np
from scipy.optimize import minimize

rng = np.random.default_rng(seed=1)
p_true, N = 0.7, 50
data = rng.binomial(2, p_true, size=N)
n0, n1, n2 = np.bincount(data.astype(np.intp), minlength=3)   # intp: portable to in-browser wasm32

def nll(p, n0, n1, n2):
    p = np.clip(p, 1e-9, 1 - 1e-9)
    return -(2*n0*np.log(1-p) + n1*(np.log(2) + np.log(p) + np.log(1-p)) + 2*n2*np.log(p))

p_analytic = (2*n2 + n1) / (2*N)
p_numeric = minimize(nll, x0=0.5, args=(n0, n1, n2),
                     bounds=[(1e-9, 1 - 1e-9)]).x.item()

print(p_true, p_analytic, p_numeric)
# 0.7   0.66   0.66

The two agree to the printed precision, and both sit a little below the true 0.7 — with N=50N = 50N=50 that gap is ordinary sampling noise, not a bug. Full version with NLL curve in code/02_mle/binomial_mle.py.

The wrinkle: where “set the derivative to zero” stops working¶

Everything above found the maximum by solving ℓ′(p)=0\ell'(p) = 0ℓ′(p)=0. That recipe quietly assumes the maximum is in the interior of [0,1][0, 1][0,1], and it need not be.

Suppose every one of the NNN observations comes back a 2 — every pair of flips was two heads. Then n0=n1=0n_0 = n_1 = 0n0​=n1​=0, and the log-likelihood collapses to ℓ(p)=2Nlog⁡p\ell(p) = 2N \log pℓ(p)=2Nlogp, which is strictly increasing: it has no stationary point anywhere in (0,1)(0,1)(0,1). Its derivative 2N/p2N/p2N/p is never zero. The maximum sits at the boundary, p^=1\hat p = 1p^​=1, and the formula p^=(2n2+n1)/2N\hat p = (2n_2 + n_1)/2Np^​=(2n2​+n1​)/2N still returns it — but by arithmetic accident, not because the derivation applies.

The estimate is also plainly overconfident. Ten such observations are twenty flips, and twenty flips of a fair coin come up all heads about once in a million times — the MLE responds by declaring the coin two-headed. MLE returns the parameter value best supported by the data it was given, which at a boundary can be a value you have no reason to believe — and there it also has no curvature left to warn you, because the Fisher information the Intuition section uses for error bars is undefined at p=1p = 1p=1.

Exercise 5 is the computational face of the same thing — an optimizer at a boundary, and a defensive np.clip that hides the divergence rather than resolving it. Setting a derivative to zero finds stationary points; only looking at LLL itself finds maxima.

Intuition¶

Why is the MLE always the sample mean for these examples? Because both Bernoulli and Binomial are members of the exponential family, where the log-likelihood is linear in a sufficient statistic (here, the count of successes). Setting its gradient to zero forces the sample average of that statistic to equal its expectation under ppp — and for Bernoulli, the expectation is ppp itself. (This generalizes: MLE for the Gaussian gives the sample mean and sample variance for the same reason.)

Why minimize NLL instead of maximize LLL? Three reasons stacked on top of each other: (1) optimizers minimize by convention; (2) log⁡\loglog turns products into sums, simplifying derivatives; (3) log⁡\loglog rescales tiny probabilities into a representable numeric range. Any one alone is reason enough.

What does MLE not tell you? It gives a single point estimate, not a distribution over plausible θ\thetaθ values. The curvature of the log-likelihood at its peak — the observed Fisher information J(θ^)=−∇2ℓ(θ^)J(\hat\theta) = -\nabla^2 \ell(\hat\theta)J(θ^)=−∇2ℓ(θ^), the negative Hessian — measures how sharply the data pin θ\thetaθ down. Its inverse J(θ^)−1J(\hat\theta)^{-1}J(θ^)−1 estimates the covariance of θ^\hat\thetaθ^; the square roots of that matrix’s diagonal are the standard errors, from which asymptotic confidence intervals follow under the usual regularity conditions. (Sharp peak, large JJJ, small variance — the inverse relationship is the whole content.) But MLE itself is silent about uncertainty until you ask. Bayesian inference (not in this book) carries a full posterior distribution as a first-class object.

MLE is a function — and a random one. p^\hat{p}p^​ depends on the random sample {Xi}\{X_i\}{Xi​}, so p^\hat{p}p^​ is itself a random variable. Its mean across resamples is the true ppp (MLE is unbiased here). Its standard deviation across resamples is the standard error, and for a Bernoulli sample mean it scales like p(1−p)/n∝1/n\sqrt{p(1-p)/n} \propto 1/\sqrt{n}p(1−p)/n​∝1/n​. This 1/n1/\sqrt{n}1/n​ shrinkage is the recurring signature of statistical estimation, and you will see it again in Chapter 3.

  2. Derivation. Suppose X1,…,Xn∼iidN(μ,σ2)X_1, \dots, X_n \overset{\text{iid}}{\sim} \mathcal{N}(\mu, \sigma^2)X1​,…,Xn​∼iidN(μ,σ2).   3. Computational.   4. Modeling judgment. A pollster surveys 1000 voters and finds 540 prefer candidate A. Solutions

1. Frequentist statistics treats θ\thetaθ as a fixed unknown constant and the data XXX as random. So “the probability that θ\thetaθ equals some value” is not even defined in this framework — θ\thetaθ has no probability distribution. The likelihood L(θ)L(\theta)L(θ) is a function of θ\thetaθ that evaluates at each candidate value to “the probability (or, for continuous data, the density) of seeing the data we saw if θ\thetaθ were that value.” It is not itself a probability distribution over θ\thetaθ (it generally doesn’t even integrate to 1 over θ\thetaθ). Bayesian statistics does give θ\thetaθ a distribution (the posterior), but only by also specifying a prior.

2. Log-likelihood for IID Gaussian:

ℓ(μ,σ2)=−n2log⁡(2πσ2)−12σ2∑i(Xi−μ)2.\ell(\mu, \sigma^2) = -\tfrac{n}{2}\log(2\pi\sigma^2) - \frac{1}{2\sigma^2}\sum_i (X_i - \mu)^2.ℓ(μ,σ2)=−2n​log(2πσ2)−2σ21​i∑​(Xi​−μ)2.
(9)

∂μℓ=1σ2∑i(Xi−μ)=0⇒μ^=Xˉ\partial_\mu\ell = \frac{1}{\sigma^2} \sum_i (X_i - \mu) = 0 \Rightarrow \hat\mu = \bar X∂μ​ℓ=σ21​∑i​(Xi​−μ)=0⇒μ^​=Xˉ. Substituting μ^\hat\muμ^​ and solving the second equation, ∂σ2ℓ=−n2σ2+12σ4∑i(Xi−μ^)2=0⇒σ^2=1n∑i(Xi−Xˉ)2\partial_{\sigma^2}\ell = -\frac{n}{2\sigma^2} + \frac{1}{2\sigma^4}\sum_i(X_i - \hat\mu)^2 = 0 \Rightarrow \hat{\sigma}^2 = \frac{1}{n}\sum_i (X_i - \bar X)^2∂σ2​ℓ=−2σ2n​+2σ41​∑i​(Xi​−μ^​)2=0⇒σ^2=n1​∑i​(Xi​−Xˉ)2. The denominator is nnn (not n−1n-1n−1); MLE for variance is biased, and the unbiased “Bessel-corrected” estimator with n−1n-1n−1 comes from a different criterion.

One caveat the stationary-point calculation hides, and it is the same trap as the boundary case above: this derivation assumes σ^2>0\hat\sigma^2 > 0σ^2>0. If every observation happens to be identical, then ∑i(Xi−Xˉ)2=0\sum_i (X_i - \bar X)^2 = 0∑i​(Xi​−Xˉ)2=0 and ℓ→+∞\ell \to +\inftyℓ→+∞ as σ2→0+\sigma^2 \to 0^+σ2→0+ — the likelihood is unbounded and no maximiser exists. Setting a derivative to zero cannot tell you that; only looking at LLL itself can.

3. See code/02_mle/standard_error_scaling.py. The slope on log-log axes should be very close to -0.5, matching SE(p^)=p(1−p)/n\mathrm{SE}(\hat p) = \sqrt{p(1-p)/n}SE(p^​)=p(1−p)/n​.

4. p^=0.540\hat p = 0.540p^​=0.540 in both cases. Standard error ≈0.540⋅0.460/n\approx \sqrt{0.540 \cdot 0.460 / n}≈0.540⋅0.460/n​: ≈0.0158\approx 0.0158≈0.0158 for n=1000n = 1000n=1000, giving a two-sigma band of ±0.032\pm 0.032±0.032, i.e. [0.508,0.572][0.508, 0.572][0.508,0.572] — clear of 0.5, so this is evidence of a real lead. For n=200n = 200n=200, ≈0.0352\approx 0.0352≈0.0352, giving ±0.071\pm 0.071±0.071, i.e. [0.470,0.610][0.470, 0.610][0.470,0.610] — which comfortably contains 0.5, so the same point estimate now supports no conclusion about who is ahead. Sample size is not a footnote. Note also how little the band shrinks for the effort: five times the respondents buys only a 5≈2.2\sqrt5 \approx 2.25​≈2.2-fold narrowing, which is the 1/n1/\sqrt{n}1/n​ tax again.

5. Both runs land on the right answer, p^=0.338\hat p = 0.338p^​=0.338 — but only one of them knows it did. Without bounds you get success=False and a message about precision loss (on SciPy 1.18 it reads 'Desired error not necessarily achieved due to precision loss.', but the exact wording is a SciPy internal and has changed between versions — read the success flag, not the string); with bounds, success=True and a clean convergence message.

The reason is the np.clip inside nll_bernoulli. Unbounded, the optimizer steps into p>1p > 1p>1, where log⁡p\log plogp and log⁡(1−p)\log(1-p)log(1−p) would be undefined — but the clip silently pins ppp to 1−10−91 - 10^{-9}1−10−9 instead. So the NLL stays finite (no NaN), and the surface out there is perfectly flat: every p>1p > 1p>1 returns the same value, the gradient is zero, and the line search cannot make progress. Hence the precision-loss warning.

The lesson is the useful part. The clip is defensive coding that prevented a crash and, in exchange, converted a loud failure into a quiet one — a flat region the optimizer had to blunder out of. bounds fixes the actual problem, by keeping the search inside the domain where the model is defined. The tiny ϵ\epsilonϵ then avoids the boundary itself, where the log-likelihood genuinely diverges. Always read result.success: an optimizer that returns a number has not necessarily converged.
