Getting your coding agent running

Budget fifteen minutes and finish with the acceptance test in §3. Your Harvard Claude account already exists, so most of that time goes on the download.

This guide is written for Claude Code, which is the course default: §1 is the desktop app and §2 is the same tool in a terminal. Do one of them. If you would rather use OpenAI’s tooling, the appendix covers ChatGPT and Codex, and either of those is fine for the course.

0. Your Harvard Claude account¶

Harvard provisions Claude through HarvardKey and you already have it. Sign in:

  1. Go to https://claude.ai/

  2. Enter your Harvard email address.

  3. Click Sign in with SSO, which appears once the email is in the box.

If you already had a Claude account on your Harvard email, you may land in your old personal workspace. Switch with the selector under your profile icon, top left.

HUIT’s own write-up is Getting Started with Claude. If sign-in fails, post on Ed before filing an IT ticket. We can usually answer faster, and whatever stopped you has probably stopped someone else.

Use your Harvard account. Personal free tiers do not include agent access, and we cannot debug a subscription we cannot see.

1. Claude Code desktop app — the default¶

No terminal required.

  1. Download from https://claude.com/download and install it. macOS and Windows have direct installers; on Linux see https://code.claude.com/docs/en/desktop-linux.

  2. Open the app and sign in with the Harvard account from §0.

  3. Point it at a folder. Make an empty one first — am215/ somewhere you can find again — and open that. An agent works inside a folder, and it can read and write the files there.

Then run the acceptance test in §3.

2. Claude Code in the terminal¶

The same tool and the same account, driven from a shell. Pick this or §1, whichever you prefer.

macOS, Linux, or WSL:

curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell:

irm https://claude.ai/install.ps1 | iex

Then check it landed, make a working folder, and start it:

claude --version
mkdir -p ~/am215 && cd ~/am215 && claude

The first run opens a browser to sign in. If something is wrong and the error does not say what, claude doctor prints a diagnostic without starting a session.

3. The two-minute acceptance test¶

Run this before you decide you are set up. In your working folder, give the agent exactly this:

Create a file called check.py that prints the numbers 1 to 10 and their squares. Then run it and show me the output.

You are ready when all three of these are true:

  1. A file called check.py is in your folder when you go and look for it on disk.

  2. The agent ran it and reported the output it got back.

  3. You can find the folder again without the agent’s help.

Code on screen with no file on disk means you have a chat interface. Try §1 once more; if that fails too, §4 describes what the chat interface costs you.

4. If your laptop will not cooperate¶

Try §1 and §2 both before giving up on the machine; the desktop app and the CLI fail for different reasons.

If neither runs, the web chat interfaces — claude.ai and chatgpt.com in a browser — will do. They cannot create files, run code, or see errors, so you will be copying output back and forth by hand. Say so on Ed, because a laptop that will not run either one is worth us knowing about.

There is also a browser-based option that needs nothing installed, described in §A4. It puts the agent inside VS Code or a Jupyter terminal, so it suits you better if you already know one of those.

5. When it goes wrong¶

What you seeWhat it usually is
Access error signing in at claude.aiYou already have access, so this is unexpected. Post on Ed.
No Sign in with SSO buttonIt appears only after you type your Harvard email.
Signed in, but everything looks like your old accountYou are in a personal workspace. Switch under your profile icon.
claude: command not found after installingClose the terminal and open a new one. If it persists, run claude doctor.
Windows: 'irm' is not recognizedThat command is PowerShell-only. PowerShell’s prompt starts PS C:\.
Signed in, but it will not write filesThe web chat has no file access. See §4.
Never used a terminal beforeUse the desktop app (§1). Nothing in this course requires a terminal.

Still stuck when section starts? Tell your TF in the first five minutes. You will pair with someone in your group whose agent runs, and you do the typing.

Stuck the night before? Post on Ed. Setup problems repeat, so one answer usually helps several people at once.

Appendix — ChatGPT and Codex¶

Skip this unless you would rather work in OpenAI’s tooling. Either tool below is acceptable for the course, and neither is better supported than Claude Code.

A1. Your Harvard ChatGPT account¶

HUIT pulled the course roster on 2 September and emailed an invitation to every student enrolled at that point. Harvard’s ChatGPT licences are not wired to Grouper, so a student who joined the roster afterwards does not get one automatically and adding them to the roster now will not trigger it. Request an account here: https://harvard.service-now.com/ithelp?id=sc_cat_item&sys_id=53b1914133a083d074dca3813d5c7b2d

Codex signs in with the same ChatGPT account.

A2. ChatGPT desktop app¶

  1. Download from https://chatgpt.com/download and install it.

  2. Sign in with the Harvard ChatGPT account from §A1.

  3. Make an empty working folder — am215/, somewhere you can find again.

Run the acceptance test in §3 before you rely on this one. The features that create and run files sit behind a specific mode, and the app also has a plain chat window with no access to your disk. §3 tells you which of the two you are in.

A3. Codex in the terminal¶

macOS or Linux:

curl -fsSL https://chatgpt.com/codex/install.sh | sh

Windows PowerShell:

irm https://chatgpt.com/codex/install.ps1 | iex

If you already have Node 18 or later, npm install -g @openai/codex works too. Start it by running codex inside your working folder and choosing Sign in with ChatGPT. Then run the acceptance test in §3.

A4. HUIT Open OnDemand — the agent in a browser¶

Open OnDemand runs a session in your browser with nothing installed on your machine. Claude Code and Codex are both preinstalled there; you sign in with your own Harvard account as usual.

You reach the agent through one of two apps. Code Server is VS Code in a browser tab, and you drive the agent from a terminal panel inside it. Jupyter Lab gives you the same environment with a Jupyter terminal instead. Either works, and both put a layer of editor between you and the agent, so this is a better fit if you already use one of them.

The link and the current status are in the Ed announcement. Two things to know before you rely on it: the sessions mount your real home directory and run with editor workspace trust turned off, so keep anything sensitive out of them; and you choose a number of hours at launch, after which the session ends.
